## lessons-learned
- [Five ways a check passed while proving nothing](lessons-learned/2026-07-31-verification-failures.md) — a measurement that failed to a plausible value (0/8 was a parse error); an A/B whose control moved 4/10 while the treatment moved 1; a mutation test that flagged the wrong line; `git add -A` silently skipping a gitignored file across three commits; a test that passed vitest and failed `tsc`. Antidote in every case: break the thing on purpose and confirm the guard notices.
- [A Report-Only CSP cannot see hosts built at runtime](lessons-learned/2026-07-30-csp-runtime-hosts-invisible-to-reports.md) — two days of Report-Only data said "nothing first-party is blocked", and enforcing would have silently killed GA4: `gtag.js` builds its transport host at runtime, so `www.google.com/g/collect` appeared in neither the source, the served HTML, nor the violation stream, and `page_view`/`scroll`/`user_engagement` were all blocked with the page rendering perfectly. Rules: validate analytics allowlists by driving a real browser under an enforcing policy, never by reading code or reports; `'unsafe-inline'` structurally blinds the report stream to inline scripts and the hosts they construct, so waiting longer cannot help; a quiet stream is ambiguous, not reassuring; CSP binds to the policy a document was delivered with, so reset the browser between policy changes.
- [A DEV database is per-machine — a connection string is not proof it exists](lessons-learned/2026-07-27-dev-db-is-per-machine.md) — a prompt-sync request could not start because `archos_labs_dev` had never been created on this laptop, while `.env.local` named it, the `archos_dev` role authenticated, and the wiki described the local DEV clone as the standing model (it was made on a different machine). Rules: confirm a database exists before diagnosing against it, `3D000` is a provisioning gap not an app bug; "which DB does this connection mean" and "does that DB exist" are two questions and only the server answers the second; write a hand-run setup sequence down the day it is run; prefer a cheap full rebuild to surgical repair. Watch item: a Render DEV Postgres kills the `127.0.0.1` = DEV rule.
- [Verify by running the thing, not by verifying the deploy](lessons-learned/2026-07-26-verify-by-running-not-by-deploying.md) — the blog agent passed a full PROD promotion checklist (backup, migration by hand, CI, deploy verified, seeds, cron) and could not produce a single post: an abort signal left armed across the response body killed every queue refill, the research came back with zero figures so the writer invented them and the grounding gate correctly refused every draft, `I have never seen` slipped past the fabricated-experience regex into PROD under an AI byline, and a parked draft silently burned a publish slot. Rules: the only check that counts is the artefact the feature exists to produce; auth on an endpoint is not auth on the function behind it; when a gate rejects everything, suspect the supply, not the filter; a human re-running until the output is good is a filter you cannot ship.
- [Writing site_setting.value with JSON.stringify(obj)::jsonb double-encodes it](lessons-learned/2026-07-19-site-setting-jsonb-double-encoding.md) — `JSON.stringify(x)::jsonb` stored a jsonb *string* wrapping the object, so `getChatPrompt` silently fell back to the placeholder prompt (Metis lost its persona; recall still worked so it hid). Rule: write jsonb objects with `sql.json()` / Drizzle values, never `JSON.stringify(x)::jsonb`; read with a `typeof==="string"` → `JSON.parse` guard.
- ["Crawled – currently not indexed" is mostly domain trust, but hygiene bugs feed it](lessons-learned/2026-07-12-seo-crawl-not-indexed-hygiene.md) — GSC's "crawled not indexed" on a young domain is Google's discretion (fix = backlinks + index requests + content depth), but a 3-agent audit found real feeders: soft-404 out-of-range pagination (200+empty), doubled brand in `<title>` (layout template + `effectiveTitle` both append), `force-dynamic` on indexable routes (cold DB per crawl), bare `JSON.stringify` on layout JSON-LD (`</script>` breakout), Article JSON-LD emitting soft-deleted image URLs, RSS CDATA double-escaping `&`, and `/search` inheriting the homepage canonical. Rules: bounded routes 404 out-of-range; titles are brand-free; indexable = ISR not force-dynamic; JSON-LD via `jsonLdScript()`; client pages need a sibling layout for their canonical.
- [Optimistic upload to a just-created conversation loses the file to two client-side races](lessons-learned/2026-07-07-attach-fresh-conversation-races.md) — attaching to a *fresh* Metis conversation silently uploaded nothing / the chip vanished mid-upload (latent since PR1; only the PR2 E2E caught it). Race 1: reading the live `input.files` FileList after `await newChat()` — the input's `onChange` clears `value=""` and empties it. Race 2: the just-created conversation's empty attachments-load raced + clobbered the optimistic chip. Fixes: snapshot `Array.from(files)` before any await; consume-once `skipAttachLoadRef`. Rule: snapshot live DOM collections before the first await; the cold/first-time path needs its own E2E.
- [LinkedIn API version header sunsets on a ~12-month clock](lessons-learned/2026-07-01-linkedin-api-version-sunset.md) — hardcoded `LINKEDIN_API_VERSION = "202402"` aged out; PROD scheduled LinkedIn posts failed with `426 NONEXISTENT_VERSION` behind the generic "LinkedIn API returned no response". Fix: `process.env.LINKEDIN_API_VERSION ?? "202606"` (env-overridable, current default). Rule: pin provider API version dates to an env var + read the server log (`[social/linkedin] publish <status>`) before trusting the UI string.
- [Next Link to the current URL is a no-op — stateful tools get stuck](lessons-learned/2026-06-29-nav-link-to-current-url-noop.md) — clicking a Tools nav link while already on that page did nothing; Next.js treats a `<Link>` to the current URL as a no-op so a `useState`-driven tool never re-mounts. Fix: in `components/layout/nav.tsx`, intercept the click on Tools links with `href === usePathname()` and force `window.location.href` reload. Rule: if a nav link can point at the current page and that page holds meaningful client state, either force a hard reload or encode state in the URL.
- [Brain recall silently failed on GBrain cold starts — "Metis doesn't remember me"](lessons-learned/2026-06-22-brain-recall-cold-start-timeout.md) — recall's two 5s timeouts (token + vector query) blew the budget whenever GBrain cold-started (same query: ~1.5s warm, >5s cold), and the failure was swallowed → zero memories → generic answers. Data was fine. Fix: widen timeouts (query 10s, token 8s), warm GBrain on workspace open via `warmBrain()` + `POST /api/brain/warm`, and log recall failures in prod. Verified: warm absorbed a 6.2s cold start, recall then returned 5 memories in ~1.8s.
- [A full-bleed canvas needs a definite height — h-full collapses under min-h-full](lessons-learned/2026-06-17-react-flow-height-collapse.md) — the Model Studio React Flow canvas rendered as a zero-height void (build + unit tests clean); only the E2E caught it. Fix: `flex-1 min-h-0` chain + `relative`/`absolute inset-0` leaf. Also documents the no-backdoor Playwright auth-via-register pattern + the in-memory register rate limit.
- [Clean build + passing tests can still 500 — the migration was never applied](lessons-learned/2026-06-16-migration-generated-not-applied.md) — `/workspace/model-studio` 500'd because `data_model` was in schema + migration file + journal, with passing tests and a clean build, but `pnpm db:migrate` was never run so the table didn't exist in the live shared DB. Rule: a clean build that 500s → check `to_regclass`, not the journal; tests and build never touch the live DB.
- [GBrain security hardening — debug endpoints, PII, and schema validation](lessons-learned/2026-06-10-gbrain-security-hardening.md) — debug endpoint shipped to prod (deleted), Zod refine on read-path schema would crash config loader (moved to point-of-use), conversations stored verbatim in external service (PII redaction added). Three rules: no debug in prod, validate at write/use not read, sanitize at the boundary.
- [CDMP question generation was sequential — independent LLM calls must run concurrently](lessons-learned/2026-06-02-cdmp-sequential-generation-slow.md) — a 19-Q exam took 6.8 min (sequential `for await`, 2 LLM calls/question); 100 Q would be ~36 min, and the slowness expired the 5-min session JWT → answers 401'd. Fix: bounded-concurrency pool (12) in `lib/cdmp/generate.ts`. Rule: never serial-loop N independent LLM calls; cap concurrency 8–16. Verified by tsc/unit tests, not yet a live run.
- [Local dev auth — CSRF needs localhost site URL, Google sign-in needs its own redirect URI](lessons-learned/2026-06-02-local-dev-auth-csrf-oauth-gotchas.md) — "Security check failed" on register = CSRF origin mismatch (set `NEXT_PUBLIC_SITE_URL=http://localhost:3007`), not Turnstile. Google `redirect_uri_mismatch` = sign-in uses `/api/auth/google/callback`, separate from the admin `/api/admin/google-oauth/cb` on the same client; whitelist both.
- [Puppeteer's postinstall flakes on a corrupt zip — pre-seed the cache instead of fighting it](lessons-learned/2026-06-02-puppeteer-postinstall-corrupt-zip-local.md) — `pnpm install` fails at `puppeteer postinstall` with `end of central directory record signature not found`; network/disk/config all fine, it's an installer bug leaving a 0-byte cache marker. Fix: `rm -rf ~/.cache/puppeteer/chrome/mac-*` then `pnpm exec puppeteer browsers install chrome`, then re-run install. Do NOT use `PUPPETEER_SKIP_DOWNLOAD` (breaks local PDF export).
- [A save path and a read path that don't share a timezone helper will drift](lessons-learned/2026-05-25-admin-list-rendered-utc-instead-of-melbourne.md) — admin posts list rendered `.toISOString().slice(...)` while the scheduled-publish picker was Melbourne-anchored, so 09:00 AEST schedules looked like prior-day 23:00 UTC. Fix: shared `lib/format-melbourne.ts`. Rule: pickers and renderers for an anchored timezone share one module — never inline `.toISOString().slice(...)` for user-facing wall-time.
- [A dynamic sitemap on a cold-starting origin will fail Googlebot's fetch budget](lessons-learned/2026-05-24-sitemap-cold-start-fetch-failures.md) — `force-dynamic` + DB queries + a Render-tier idle origin meant every infrequent Googlebot fetch raced a cold start; Bing's longer timeout posture hid the asymmetry. Rule: routes serving infrequent eventually-consistent traffic to bots must be edge-cacheable (sitemaps, robots, llms.txt, feeds, OG images, `.well-known`).
- [Validation without normalization is half a feature](lessons-learned/2026-05-24-validation-without-normalization.md) — featured-image upload shipped a 500 KB hard cap with no compression, blocking publishing of a 2,120 KB PNG. Fix: server-side Sharp pipeline ([[image-pipeline]]). Rule: when validation rejects realistic inputs, owe the user the normalization step that lets them succeed.
- [Inspect third-party installer scripts before running them](lessons-learned/2026-05-21-third-party-installer-inspection.md) — gstack install surfaced three gotchas the one-liner hid: Bun prerequisite, nested-negation gitignore trap, PowerShell-only SessionStart hook on Linux. Rule: `gh api .../contents/setup | base64 -d` BEFORE running any third-party installer.
- [Adding a top-level app/ route requires updating RESERVED_SLUGS (or 404s become 500s)](lessons-learned/2026-05-21-reserved-slugs-drift-causes-500s.md) — Pages CMS catch-all's boot check throws if any top-level app/ dir is missing from RESERVED_SLUGS. Static routes hide the bug from normal traffic; only catch-all renders surface it. Rule: every new app/ folder gets a RESERVED_SLUGS entry in the same PR.
- [Don't assume multi-environment architecture — read deployment-architecture first](lessons-learned/2026-05-20-single-db-architecture.md) — Phase C debacle post-mortem; the conventional dev/staging/prod assumption broke when reality was single-env, single-DB. Rule: when the user names architecture, accept it at face value; don't reinterpret through a conventional lens.
- [Drizzle raw `sql` template rejects Date bind parameters](lessons-learned/2026-05-18-drizzle-raw-sql-rejects-date-params.md) — postgres.js's `.str()` throws `ERR_INVALID_ARG_TYPE` on Date params via raw `sql` template; use the typed query builder, or convert Date → ISO string + `::timestamptz` cast; unit-mocking `getDb` does not exercise the driver
