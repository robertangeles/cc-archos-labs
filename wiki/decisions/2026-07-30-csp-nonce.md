`script-src` no longer carries `'unsafe-inline'`. `proxy.ts` mints a fresh nonce per request, sets the policy itself, and forwards the nonce to the app on `x-nonce`. This closes the gap [[2026-07-30-csp-enforcing]] left open the same day.

## What made it cheap

[[2026-07-30-csp-enforcing]] recorded this as an architectural decision with a real cost, on the reasoning that nonces force dynamic rendering and would undo the blog ISR work. **That reasoning was wrong, and checking it is what unblocked this.** Every one of the 51 route files already carries `export const dynamic = "force-dynamic"`, and production returns `private, no-cache, no-store` on `/`, `/about`, `/consulting`, `/contact` and `/blog`. The ISR conversion had been built, measured and reverted. There was no static rendering left to lose, so the headline cost did not exist.

## Design: nonce, not 'strict-dynamic'

The textbook strict CSP is `'nonce-X' 'strict-dynamic' https: 'unsafe-inline'`, which makes the host allowlist irrelevant. Rejected, for a reason specific to this site: `'strict-dynamic'` makes browsers **ignore** host allowlists and trust only script injected by already-trusted script. Cloudflare injects a bot-management script into our pages at the edge, after our HTML is generated — we never see it and cannot nonce it. Keeping the host allowlist keeps it working.

Confirmed in practice: Turnstile's `api.js` loads on `/login` in DEV with **no nonce**, and runs, because the host is allowlisted. Under `'strict-dynamic'` that class of script is where breakage would have come from.

`style-src` keeps `'unsafe-inline'`. Next.js and the font loader emit inline styles that are not nonce-able without a much larger change, and inline CSS is a far weaker vector than inline script. Recorded so it reads as a decision, not an oversight.

## The two things that had to be right

**Next.js needs the policy on the REQUEST, not just the response.** That is how it discovers the nonce and stamps it on the ~30 script tags it emits per page (RSC flight data, bootstrap). Verified: 32 of 34 tags carry the nonce. The 2 without are `application/ld+json`, which browsers do not execute and `script-src` therefore does not govern — checked empirically, the 4-node entity graph still parses out of the DOM.

**Exactly one policy.** The CSP came out of `next.config.ts` entirely; two `Content-Security-Policy` headers are each enforced independently, so a resource must satisfy both. The other five headers stay there, since they are the same string every request.

## The regression a test caught

Widening the matcher from `/admin/:path*` to everything turned `path.startsWith("/admin")` into a live trap: it also matches `/administrator-notes` and `/admin-guide`, which would have been redirected to the login page. Safe before only because the matcher never fed those paths in. No such route exists today, so nothing would have looked broken until someone added one. Fixed with segment-boundary matching (`=== "/admin" || startsWith("/admin/")`).

A first pass at the matcher also hand-maintained a list of asset extensions to skip, and silently dropped the CSP from `/sitemap.xml` and `/robots.txt`. Replaced with `/((?!_next/static|_next/image).*)` — skip only Next's own build output, no judgement calls about which extensions can execute script.

## Verification

- 10 pages driven in a real browser under nonce-only `script-src`: **0 violations**; `gtag` a function, GTM initialised, `dataLayer` populated, entity graph parsing
- Auth gate intact: `/admin` and `/admin/blog` → 307 to `/admin/login`; `/admin/login` 200; `/api/admin/posts` 401; `/api/admin/login` 405. `/administrator-notes` and `/admin-guide` 404, not redirected
- CSP present on `/`, `/admin`, `/admin/login`, `/api/admin/posts`, `/sitemap.xml`, `/robots.txt`, `/llms.txt`; absent on `_next/static` as intended
- Nonce differs per request and matches between header and `x-nonce`
- 28 new tests (`lib/csp.test.ts`, `tests/proxy.test.ts`); full suite 152 files / 1881 tests

## What is genuinely not covered

Inline **styles** remain open (`style-src 'unsafe-inline'`). GTM can still inject a tag from a host the allowlist does not cover — unchanged by this work, and why reporting stays wired. Neither is a loose end in this change; both are stated properties of it.
